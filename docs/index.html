Documentation

How to bring these templates into your own Ivanti Neurons for ITSM environment, and how the repository is organized under the hood.

Getting started

  1. Pick a design (currently Spectrum) and a module page for the notification you need.
  2. Open the template — either click through to it live, or find its file under Spectrum/<Module>/<file>.html in the repository.
  3. Copy the file's full HTML contents into the matching notification's HTML body field inside Ivanti Neurons for ITSM.
  4. Replace the placeholder logo URL, company name, and every https://your-itsm-system.com/... link with your own environment's values.
  5. Map the example field values (ticket ID, requester name, priority, dates, etc.) to your actual Ivanti field tokens.
Every template is self-contained: a single root <div>, table-based layout, no external stylesheets, no build step. It's meant to be pasted as-is.

Ivanti placeholder syntax

Priority and status badges use Ivanti's native conditional syntax so they render dynamically inside the platform — this is real Ivanti template syntax, not a placeholder for illustration: 

$(If Priority == 1
  Then '<span style="...">1 - High</span>'
  Else (If Priority == 2
    Then '<span style="...">2 - Medium</span>'
    Else '<span style="...">3 - Low</span>'))

The same pattern is used for other conditional fields across the library (SLA status, service request status, etc.) — search for $(If inside any template to find every dynamic field.

Bilingual (English / Arabic) structure

Every template renders both languages in a single email: a full English section, a dashed "عربي" divider, then a full right-to-left Arabic section — so one file serves both audiences without duplicating templates per language. Arabic sections carry dir="rtl" and mirror text alignment (left/right swapped) rather than reusing the English layout verbatim.

Repository structure

My Templates/
├── README.md              ← project overview
├── CLAUDE.md               ← detailed design-system reference
├── index.html               ← this site's homepage
├── designs/                   ← one folder per site page: designs gallery,
│   └── spectrum/                per-design overview, per-module browsing
│       ├── incident/
│       ├── service-request/
│       └── ...
├── docs/, about/               ← this page, and the About page
├── assets/                     ← shared site CSS/JS
└── Spectrum/                      ← design #1's actual template content
    ├── Incident/
    ├── Service Request/
    └── ...

Spectrum/ holds nothing but pure, Ivanti-pasteable template files — no site chrome. Everything else (index.html, designs/, docs/, about/, assets/) exists only to make the templates browsable and previewable as a website.

Color system

Spectrum assigns one accent-color gradient per module, so ticket type and severity are readable before an email is even opened — amber for "needs your input", emerald for a good outcome, red for rejected/low-satisfaction, deepening toward maroon as an Escalation approaches an SLA breach. See the swatches on the Spectrum overview page for the full key.
